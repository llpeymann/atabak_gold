# راهنمای دمو — Atabak Gold (فازهای ۱ تا ۷)

این سند دقیقاً همان چیزی است که برای دیدن رفتار واقعی پروژه لازم است: دمو از **کد واقعی** استفاده می‌کند و
فقط دو مرز شبکه‌ای (ارسال به پلتفرم و دریافت قیمت) را شبیه‌سازی می‌کند.

---

## ۱) پیش‌نیازها

* Node.js **۲۰ یا بالاتر** (همان `engines.node` پروژه؛ روی Node 22 هم تست شده است).
* نصب وابستگی‌ها **با devDependencies** (دمو از `@nestjs/testing` برای جانشینی حامل استفاده می‌کند):

```bash
npm ci
```

* هیچ اعتبارنامه، هیچ توکن و هیچ دسترسی شبکه‌ای لازم نیست. دمو آفلاین کار می‌کند.

## ۲) اجرا در سه حالت

```bash
# ۱) داشبورد وب (پیش‌فرض) — http://0.0.0.0:3210
npm run demo

# ۲) اجرای خط فرمان همهٔ سناریوها (مناسب تأیید سریع)
npm run demo -- --run all

# ۳) یک سناریو + خروجی ماشین‌خوان
npm run demo -- --run referral-rewards
npm run demo -- --json --run all

# فهرست سناریوها
npm run demo -- --list
```

* `npm run demo` خودش `nest build` را اجرا می‌کند و سپس `dist/demo/main.js` را بالا می‌آورد.
* تغییر پورت: `DEMO_PORT=4000 npm run demo`
* تغییر محل داده: `DEMO_DATA_DIR=/tmp/my-demo npm run demo` (پیش‌فرض: `<tmp>/atabak-demo`)
* توقف سرور: `Ctrl+C`

> **نکتهٔ ایمنی:** دمو پوشهٔ کاری خود را به `DEMO_DATA_DIR` منتقل می‌کند؛ بنابراین `.env` واقعی مخزن
> خوانده نمی‌شود، داده‌های تولیدی دست‌نخورده می‌مانند و توکن واقعی وارد هیچ بخشی از اجرا نمی‌شود.

## ۳) چه چیزی واقعی است و چه چیزی شبیه‌سازی؟

| بخش | وضعیت در دمو |
| --- | --- |
| پیکربندی و اعتبارسنجی محیط | **واقعی** — همان `validateEnvironment` زمان boot |
| خط لولهٔ قیمت (پارسر → نرمال‌سازی → بازرسی → وضعیت بازار → خروجی قابل انتشار) | **واقعی**، با ورودی **DEMO** برچسب‌دار |
| موتور هشدار، ویزارد، صفحه‌ها، روتر بات | **واقعی** |
| موتور کانال (کلید یکتای کار، claim اتمیک، نتیجهٔ هر مقصد، جلوگیری از تکرار) | **واقعی** |
| موتور دعوت/پاداش و ظرفیت مؤثر هشدار | **واقعی** |
| دریافت قیمت از سرویس بیرونی | **غیرفعال** (`DemoPriceService` در دمو خطا می‌دهد؛ سناریوها داده را تزریق می‌کنند) |
| ارسال به بله/تلگرام | **شبیه‌سازی** — `DemoBotApiClient` و `DemoBaleService` همهٔ ارسال‌ها را ثبت می‌کنند |
| دادهٔ قیمت | ساختگی و **برچسب‌دار DEMO** (اعداد گرد و آشکارا آزمایشی، داخل بازه‌های عقلی مستندشدهٔ هر نماد) |

پیام‌ها و قیمت‌های DEMO هرگز به‌عنوان دادهٔ واقعی نمایش داده نمی‌شوند: UI دمو و خروجی JSON هر دو با
`note` و برچسب `DEMO` مشخص می‌کنند که داده ساختگی است.

## ۴) سناریوها و خروجی مورد انتظار

| # | شناسه | چه چیزی را نشان می‌دهد | خروجی مورد انتظار |
| --- | --- | --- | --- |
| ۱ | `overview` | فازها، مستندات و آخرین نتیجهٔ واقعی تست‌ها | فهرست ۸ فاز با خط وضعیت + اعداد `docs/audit/TEST_RESULTS.json` |
| ۲ | `config` | پیکربندی اعتبارسنجی‌شده، سلامت، موجودی فروشگاه‌ها | جدول بدون رمز + `status=ok` + شمارش کاربر/دعوت/هشدار |
| ۳ | `price-accepted` | گذر دادهٔ معتبر از کل خط لولهٔ فاز ۱ | `publishable=true`، ۱۶ نماد پذیرفته، صفر رد، متن پیام واقعی |
| ۴ | `price-rejected` | رد شدن ساختار خراب، قیمت نامعقول و پرش غیرمنطقی | `INVALID_SCHEMA` / `INVALID_PRICE` + `MISSING_SYMBOL` / `EXCESSIVE_CHANGE` و **ماندن قیمت معتبر قبلی** |
| ۵ | `bot-conversation` | منو، صفحه‌ها، ویزارد هشدار، صفحهٔ کانال، دکمهٔ دعوت | ترانسکریپت ۷ پاسخ واقعی روتر + لینک‌های بله/تلگرام |
| ۶ | `alert-lifecycle` | ساخت هشدار → عبور از آستانه → اعلان یک‌باره | ۰ اعلان زیر آستانه، **۱ اعلان** روی عبور، ۰ اعلان تکراری، `SENT` |
| ۷ | `publication` | انتشار کانال با نتیجهٔ هر مقصد + جلوگیری از تکرار | `PUBLISHED` با `bale=SENT`/`telegram=SENT`، اجرای دوباره → `DUPLICATE_PUBLICATION`، خرابی عمدی تلگرام → نتیجهٔ مستقل |
| ۸ | `referral-rewards` | سه دعوت موفق، پاداش دائمی، اثر روی ظرفیت هشدار | ردیف پاداش `GRANTED`، اعلان تبریک، **ظرفیت ۳ → ۴**، صفحهٔ «دعوت‌های من»، خوددعوتی بی‌اثر |

هر سناریو **از حالت تازه** اجرا می‌شود (کانتکست dispose و پوشهٔ داده پاک می‌شود) تا نتیجه تکرارپذیر باشد.

## ۵) پوستهٔ وب

* صفحهٔ اصلی: کارت هر سناریو + دکمهٔ اجرا، دکمهٔ «اجرای همهٔ سناریوها» و «پاک‌سازی و شروع تازه».
* خروجی نمایش‌داده‌شده: وضعیت `PASS/FAIL`، گام‌های ✔/✘، ترانسکریپت گفت‌وگو، فهرست ارسال‌های ثبت‌شده، و
  JSON کامل نتیجه.
* صفحه هیچ منبع خارجی (CSS/JS/فونت) ندارد؛ پشت پراکسی هم بی‌مشکل کار می‌کند.

## ۶) API دمو (اگر ترجیح می‌دهید با curl کار کنید)

```bash
curl -s localhost:3210/api/scenarios
curl -s -X POST localhost:3210/api/run     -H 'content-type: application/json' -d '{"id":"publication"}'
curl -s -X POST localhost:3210/api/run-all
curl -s -X POST localhost:3210/api/reset
curl -s localhost:3210/api/capture
```

## ۷) تأیید خودکار (بدون پوسته)

```bash
npm run demo -- --run all     # خروجی انسانی
npm run demo -- --json --run all   # خروجی JSON برای CI
echo $?                       # ۰ = همهٔ سناریوها PASS
```

نتیجهٔ واقعی روی همین درخت: **۸ از ۸ سناریو PASS**.

## ۸) دلایل اجرانشدن در حالت دمو (و راه بستن آن‌ها)

| مورد | چرا در دمو نیست | چطور می‌توان واقعی تست کرد |
| --- | --- | --- |
| ارسال واقعی به بله | نباید بدون اجازهٔ صریح به کانال واقعی پیام برود | با `BALE_BOT_TOKEN`/`BALE_CHANNEL_ID` یک کانال **آزمایشی** بسازید و اپ را با `npm run start:prod` اجرا کنید؛ مسیر انتشار همان مسیر واقعی است |
| ارسال واقعی به تلگرام | همان دلیل | `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHANNEL_ID` آزمایشی |
| قیمت زنده | دمو نباید به سرویس بیرونی وابسته باشد | `PRICE_API_URL` واقعی را ست کنید و `npm run start:prod` را اجرا کنید؛ همان خط لوله اجرا می‌شود |
| تأیید زنده روی Wire واقعی HTTPS | نیاز به تنظیم میزبان آزمون و گواهی | در فازهای ۶ و ۷ همین کار انجام شده است (ریگ خارج از مخزن، ۴۱ بررسی)؛ برای تکرار، `/etc/hosts` را به یک mock محلی اشاره دهید و `NODE_EXTRA_CA_CERTS` را ست کنید |

## ۹) عیب‌یابی

| نشانه | علت احتمالی | راه‌حل |
| --- | --- | --- |
| `Demo failed: ... ENOENT dist/demo/main.js` | build اجرا نشده | `npm run build` یا همان `npm run demo` را دوباره اجرا کنید |
| `EnvironmentValidationError` | مقدار محیطی نامعتبر در محیط اجرا | دمو مقادیر خودش را ست می‌کند؛ مطمئن شوید `DEMO_USE_REAL_ENV`-گونه‌ای تعریف نکرده‌اید و در ریشهٔ مخزن اجرا می‌کنید |
| پورت اشغال است | سرور دموی دیگری در حال اجراست | `DEMO_PORT=4000 npm run demo` |
| خروجی `FAIL` در یک سناریو | تغییری در رفتار پروژه | خودِ نتیجه خطا را نشان می‌دهد؛ `docs/KNOWN_ISSUES.md` را ببینید |
